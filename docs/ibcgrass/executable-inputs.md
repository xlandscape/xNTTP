# IBCgrass Executable Inputs

## Short Answer

`IBCgrassGUI.exe` does not read the xNTTP `.xrun` file or the PFT Excel workbook directly. For every patch, the
`IbcGrass` component creates a working directory, copies the executable into it, prepares text files, and starts the
executable with 18 positional command-line arguments.

The executable's immediate file inputs are:

1. one generated PFT trait file, whose name is supplied as command-line argument 5; and
2. `AppRate.txt` when `EffectModel=2` (dose response), or `HerbFact.txt` when `EffectModel=0` (text-file effects).

In the current xNTTP configuration, `EffectModel` is fixed to `dose-response`. Therefore, the actual files consumed by
each invocation are a generated `*_control.txt` or `*_treatment_MC<n>.txt` PFT file and the generated `AppRate.txt`.
Users should not prepare files inside a run workspace manually.

## Preparation Ownership

| Input or file | Prepared by | User responsibility |
| --- | --- | --- |
| Ecotox dose-response files | Manually maintained scientific input | Supply and validate species-level EC50 and slope estimates for each available endpoint |
| `ibc/pft.xlsx` | Manually maintained template | Supply ecological and life-history traits for the PFT communities |
| Case-specific PFT workbook | `ibc/prepare_pft.py` | Generate it from the template and ecotox files, then select it with `PFT` in the `.xrun` file |
| Landscape scenario selected by `Project` | Manually maintained scenario package | Select a suitable scenario and ensure its coordinates match the patch centres |
| Pesticide-use and drift parameters | xNTTP `.xrun` parameterisation | Set application years and rate, buffer, drift model, wind direction, and patch coordinates |
| Spray-drift exposure array | xNTTP components | Generated by `PpmCalendar` and `SprayDrift`; no manual IBCgrass file preparation |
| `IBCgrassGUI.exe` in each patch directory | `IbcGrass` component | None; copied from `model/variant/IbcGrass/module` |
| `<sheet>_control.txt` | `IbcGrass` component | None; generated from one workbook sheet |
| `<sheet>_treatment_MC<n>.txt` | `IbcGrass` component | None; generated from one workbook sheet for each IBCgrass repetition |
| `AppRate.txt` | `IbcGrass` component in dose-response mode | None; derived from the SprayDrift exposure at the patch centre |
| `HerbFact.txt` | `IbcGrass` component in text-file mode | None; generated from six component inputs, although this mode is not selected by the current `mc.xml` |
| 18 command-line arguments | `IbcGrass` component | Set exposed `.xrun` values; model defaults remain in `model/variant/mc.xml` |

## Runtime Directory

For each Monte Carlo run and each patch coordinate pair, the component creates a directory with this pattern:

```text
run/<SimID>/mcs/<MC-name>/work/ibc/<patch-index>/
```

The executable is launched with that directory as its current working directory. Fixed names such as `AppRate.txt` and
`HerbFact.txt` are therefore resolved there. A dose-response directory typically contains:

```text
IBCgrassGUI.exe
AppRate.txt
field-edge_control.txt
field-edge_treatment_MC1.txt
field-edge_treatment_MC2.txt
field-edge_treatment_MC3.txt
Arrhenatheretalia_control.txt
Arrhenatheretalia_treatment_MC1.txt
...
```

The component runs every sheet in the selected workbook. With three sheets, three repetitions, and one patch, it
starts 3 x 3 x 2 = 18 executable processes: a control and treatment for every sheet and repetition.

## PFT Trait Files

### Template and Scientific Sources

The value of the `.xrun` parameter `PFT` points to an Excel workbook. The supplied workbook, `ibc/pft.xlsx`, currently
contains the sheets `field-edge`, `Arrhenatheretalia`, and `Calthion`. Each sheet represents one community scenario;
each row after the header represents one PFT.

Use `ibc/prepare_pft.py` to combine this template with case-specific ecotox dose-response files. See
[PFT Preparation](pft-preparation.md) for the complete workflow. When maintaining a template, keep these properties:

- use an `.xlsx` workbook;
- use a unique, file-name-safe sheet name for each community scenario;
- keep exactly the 43 expected columns in their existing order;
- keep the header names unchanged because the adapter checks the complete header tuple; and
- avoid whitespace inside text fields because the executable parses generated rows as whitespace-separated values.

The required column groups are:

| Columns | Content |
| --- | --- |
| 1-3 | `ID`, `Species`, `MaxAge` |
| 4-17 | Allocation, mass, dispersal, establishment, growth, resource, and threshold traits |
| 18-24 | Clonality, sexual reproduction, spacer, and resource-sharing traits |
| 25-27 | `sens`, `allocroot`, `allocshoot` |
| 28-39 | EC50 and slope pairs for biomass, seedling biomass, survival, establishment, sterility, and seed number |
| 40-43 | `FlowerWeek`, `DispWeek`, `GermPeriod`, `Overwintering` |

In dose-response columns 28-39, a scalar is copied directly. A string of the form `[minimum;maximum]` is replaced by a
random uniform draw independently for each generated control or treatment file. This is how parameter uncertainty is
introduced for the individual IBCgrass repetitions.

The generated workbook stores `random` in `sens` for every PFT. When preparing the immediate text files, the component
converts this categorical value to numeric sensitivity `1`, which allows the C++ parser to read the following EC50 and
slope columns. This conversion does not assign a test species and does not make every PFT share one dose-response
curve. Dose-response uncertainty is represented by independent draws from each endpoint parameter interval for each
PFT and repetition.

The biological rationale is that regulatory test species have no known one-to-one mapping to grassland PFTs. The
current interval sampler is a legacy approximation of random assignment, not discrete selection of complete observed
test-species curves: EC50/slope pairing and test-species identity across endpoints are not retained. See
[PFT Preparation](pft-preparation.md#biological-interpretation) for the implications.

### Generated Immediate Files

The component converts each worksheet to ASCII, tab-separated text. For a sheet named `<sheet>`, it generates:

- `<sheet>_control.txt`; and
- `<sheet>_treatment_MC1.txt` through `<sheet>_treatment_MC<MCruns>.txt`.

The header is retained. Argument 5 tells the executable which one of these files to read for the current process.
Control and treatment are not encoded by different file structures; argument 15 selects control or treatment behavior.

!!! note "Compatibility detail"
    The byte-identical C++ source associated with the bundled executable attempts to read a 44th trait named
    `comp_power`. The current workbook and adapter intentionally export 43 columns. When the final extraction reaches
    end-of-line, the C++ object's constructor default of `comp_power=1` remains in effect. Do not add a 44th workbook
    column without updating the adapter's strict header check and testing the complete model.

## Dose-Response Exposure File

In the current `EffectModel=2` workflow, `AppRate.txt` contains one numeric application rate per line and no header. The
executable reads these values as its annual application-rate timeline.

The component prepares the file as follows:

1. Convert each `PatchCenterX` and `PatchCenterY` pair to an index in the SprayDrift exposure grid.
2. Read the daily exposure time series for the corresponding 1 m by 1 m cell.
3. Find days with non-zero exposure and derive their calendar years and ISO weeks.
4. Require no more than one non-zero exposure event per year and require all events to occur in the same ISO week.
5. Derive the warm-up duration from the first exposure year minus `SimulationFirstYear`.
6. Write non-zero exposure values in chronological order, then write zeroes up to `SimulationLastYear`.

For example:

```text
12.4
8.9
0
```

The input exposure has unit `g/ha`. The C++ reader stores decimal values, but the current dose-response calculation
subsequently assigns each annual rate to an integer, truncating any fractional part.

The following `.xrun` parameters influence `AppRate.txt`:

| Parameter | Influence |
| --- | --- |
| `Project` | Supplies landscape geometries and coordinate reference information |
| `ApplicationFirstYear`, `ApplicationLastYear` | Define years in which application events are generated |
| `ApplicationRate` | Supplies the nominal field rate before drift transport |
| `InCropBuffer` | Changes treated field geometry |
| `SprayDriftModel` | Selects the drift calculation |
| `WindDirection` | Controls the direction of drift transport |
| `PatchCenterX`, `PatchCenterY` | Select the exposure cell used by each IBCgrass patch |
| `SimulationFirstYear`, `SimulationLastYear` | Bound the IBCgrass timeline and generated annual-rate file |

## Text-File Effect Input

When `EffectModel=0`, the executable reads `HerbFact.txt` instead of `AppRate.txt`. The component writes this header and
six tab-separated factors:

```text
Biomass Mortality SeedlingBiomass Establishment SeedSterility SeedNumber
```

The six values come from `HerbFactorBiomass`, `HerbFactorMortality`, `HerbFactorSeedlingBiomass`,
`HerbFactorEstablishment`, `HerbFactorSeedSterility`, and `HerbFactorSeedNumber` in `mc.xml`. The PFT workbook's `sens`
value is also converted to a numeric sensitivity for each generated PFT file.

This is a dormant alternative in the present repository: `mc.xml` fixes `EffectModel` to `dose-response`, and these
factors are not exposed in `parameters.xsd` or `template.xrun`.

## Command-Line Arguments

Every executable process receives the following positional arguments after the executable path:

| Position | Executable parameter | Value prepared by xNTTP |
| ---: | --- | --- |
| 1 | `ModelVersion` | Fixed to `3` in the component |
| 2 | `CellNum` | `CellNum` from `mc.xml`, currently `173` |
| 3 | `Tmax` | Initialisation duration + inclusive simulation span + recovery duration |
| 4 | `Tinit` | Warm-up years derived from the first non-zero exposure year in dose-response mode |
| 5 | `NamePftFile` | Generated control or treatment PFT text filename |
| 6 | `seedsPerType` | `.xrun` parameter `SeedsPerType` |
| 7 | `meanBRes` | `MeanBRes` from `mc.xml`, currently `90` |
| 8 | `meanARes` | `MeanARes` from `mc.xml`, currently `100` |
| 9 | `Aampl` | `Aampl` from `mc.xml`, currently `0` |
| 10 | `AreaEvent` | `AreaEvent` from `mc.xml`, currently `0.1` |
| 11 | `GrazProb` | `GrazProb` from `mc.xml`, currently `0.01` |
| 12 | `NCut` | `Ncut` from `mc.xml`, currently `1` |
| 13 | `week_start` | Common ISO week of non-zero exposure minus 10 |
| 14 | `HerbDuration` | Inclusive span from `SimulationFirstYear` through `SimulationLastYear` |
| 15 | `HerbEffectType` | `0` for a control process; `1` for a treatment process |
| 16 | `EffectModel` | `2` for current dose-response mode; `0` for text-file mode |
| 17 | `scenario` | Zero-based index of the workbook sheet |
| 18 | `MCrun` | One-based IBCgrass repetition number |

## Current Constraints and Checks

The current component implementation assumes:

- at least one non-zero exposure event exists at every selected patch;
- no more than one non-zero exposure day occurs in a calendar year;
- all non-zero events across years occur in the same ISO week;
- X and Y patch lists have equal lengths; and
- coordinates index a valid cell of the exposure array.

It does not currently preserve a zero-exposure gap between two non-zero application years: non-zero values are packed
at the start of `AppRate.txt`, followed by zeroes. Use consecutive application years with this adapter.

!!! warning "Timeline consistency"
    `Tmax` is calculated before exposure-derived warm-up values are applied, while `HerbDuration` is passed as the full
    inclusive simulation span and `AppRate.txt` starts after warm-up. These quantities can disagree for parameter sets
    other than the current pattern. Before using different initialisation, application, or recovery periods, inspect
    the generated `AppRate.txt` and run logs and confirm that the number of rates covers every treatment year expected
    by the executable.

## Evaluation Summary

Only the scientific source data require manual preparation: principally the ecological PFT template, endpoint ecotox
studies, and selected landscape scenario. `prepare_pft.py` combines the first two into a case-specific workbook. The
`.xrun` file selects that workbook and defines simulation, application, drift, and patch parameters. The xNTTP
component chain then prepares all immediate executable inputs automatically. Editing generated PFT text files or
`AppRate.txt` inside `run` is neither necessary nor reproducible; such changes are overwritten by the next run.
