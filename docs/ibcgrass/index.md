# IBCgrass Intro

## Role in xNTTP

IBCgrass is an individual-based grassland community model. Within xNTTP, it is used to evaluate how spatially explicit
herbicide exposure can influence simulated plant communities over time.

The `IbcGrass` component is the adapter between the Landscape Model workflow and the IBCgrass engine. It receives the
daily spray-drift exposure grid and a list of patch-centre coordinates. For each selected location, it prepares a model
run using the corresponding exposure time series and the configured plant functional type data.

## Model Representation

IBCgrass represents plant communities through **plant functional types (PFTs)** and simulates individual plants under
competition for above-ground and below-ground resources. The xNTTP integration exposes settings for establishment,
management, herbicide effects, recovery, repetitions, and parallel processing.

PFTs describe ecological strategies in the simulated grassland; they are not the regulatory test species used in an
ecotoxicology study. There is therefore normally no evidence-based one-to-one correspondence between a PFT and a
tested species' dose-response function. The `random` sensitivity option represents this uncertain transfer from the
set of test-species responses to the modeled PFTs. See [PFT Preparation](pft-preparation.md) for the biological
interpretation and the exact sampling implemented in xNTTP.

## Integration Boundary

The xNTTP run controls:

- simulation years and spatial patch locations;
- the PFT input workbook and annual seed input;
- exposure generated by the SprayDrift component; and
- selected IBCgrass runtime settings from `model/variant/mc.xml`.

IBCgrass writes its native simulation outcomes below the component processing directory for the current Monte Carlo
run. Detailed interpretation of those outcome files can be added as the documentation grows.
